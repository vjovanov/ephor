# DA-001-runtime-bound-default: the runtime is a bound default, not a named coupling

**Status:** Accepted
**Date:** 2026-08-13

The old §FS-005-dispatch lead named rhei outright — "named here rather than
hidden behind an interface" — on the argument that a forge is a property of
a person's employer and may not be named, while the runtime that executes
their work is a property of how they choose to work. §REQ-001-boundary
reverses that stance: the runtime is a **binding** like every other
capacity ephor does not embody, with rhei as the shipped default
(§REQ-001-boundary.1), confined to one module by §AR-007-runtime. The
rewritten §FS-005-dispatch lead states the new position; this record keeps
the old one visible and names what the reversal costs.

## 1. Why it reversed

The law admits no exceptions: every capacity ephor lacks crosses a seam,
and every seam has the same four-part anatomy (§REQ-001-boundary.1). A
runtime carved out as the one named dependency would give the boundary an
asterisk — every future seam would have to argue why it is not also
special. The old lead's real insight — that the coupling is a file format,
not a process — was already the seam's contract in materials; the reversal
completes the anatomy around it: a configured binding (`work.runner`), a
shipped default (rhei, wired and ready), and a stated degrade (no runner:
tickets are still written, read, and reopened on disk, and running refuses
with the configured runner named).

## 2. What stays

Choosing a runtime remains a property of how a person works, which is why
one ships wired and ready — requiring a person to pick before dispatch
works would be something else (§FS-005-dispatch). Nothing rhei-shaped is
taken away: the default is bound, not removed.

## 3. The cost

One indirection — a `work.runner` binding resolves where a literal call
sufficed, and every runtime-shaped assumption must live inside the adapter
module rather than wherever it was convenient (§AR-007-runtime). And the
plan language is now a public contract: once any runner can be bound, the
plan file format, the runner invocation, and the verdict read-back stop
being an implementation detail shared with one tool and become the seam's
documented surface — the entire coupling, stated as such in the
§FS-005-dispatch lead, to be kept compatible like any published interface.
